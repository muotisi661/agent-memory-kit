# 05 · 维护：让系统自己照顾自己

记忆系统不是装好就不管的。它会自然腐化：文件重复、引用失效、标签混乱、索引过期。靠人记得去整理是不现实的 —— 必须交给定时任务。

## 四个定时任务（抽象版）

不需要照抄频率，需要照抄**职责划分**。

### 任务 A · 会话同步（每 2 小时）

**职责**：把有实质内容的对话摘要落盘到 `memory/session-notes/`。

提示词要点：

```markdown
1. 浏览最近的会话记录
2. 跳过简短问候、测试、无结论的对话
3. 每个有价值的会话写一份摘要：YYYY-MM-DD-主题.md
4. 只记录：做了什么、为什么这么决定、留下了什么坑
5. 不复制完整对话，不写"用户问…我回答…"这种流水账
6. 报告：处理了 N 个会话，写入 M 个文件
```

**关键约束**：这个任务**只允许写**，不允许移动或删除任何文件。同步任务一旦有删除权限，就会在某天顺手"整理"掉你的记忆。

### 任务 B · 知识库整理（每天深夜）

**职责**：合并高相似度文件、补全缺失标签。

```markdown
1. 扫描所有 .md（排除白名单目录）
2. 计算文件名相似度 + 内容相似度
3. 相似度 > 80% 的文件对：合并到更完整的一份，删除另一份
4. 对没有 tags 字段的文件补标签（不要动已有标签）
5. 报告写入 archive/reports/
```

**必须配置保护白名单**：

```markdown
## 🚫 绝对不能移动/删除/重命名
- memory/          ← 记忆本体
- kernel/          ← L0
- archive/         ← 归档
- scripts/         ← 脚本
- index.md         ← 主索引
- changelog.md     ← 变更日志
```

> **真实事故**：整理任务把 `agent-memory/` 目录下的文件当成"待分类笔记"，全部移到 `wiki/entities/`。记忆系统看起来完好（文档都在），实际数据已经被搬走，会话读不到任何东西。加白名单是唯一可靠的防御 —— 靠提示词里写"注意不要动"，模型总会忘。

### 任务 C · 占用率监控（每天早上）

**职责**：只报告，不动手。

```markdown
1. 读取 L0 当前字符数和上限
2. 计算占用率
3. 输出 <300 字符的报告：
   - 占用率
   - L1 各目录文件数
   - 超过 85% 就提示"建议执行 amk.py promote"
4. 不要自己执行迁移（定时任务环境里改记忆风险太高）
```

**为什么定时任务不该自己做迁移**：它在无人监督下运行，一旦判断失误（比如把安全约束下沉了），代价是之后所有会话都少了这条保护。人机协同：机器负责提醒，人（或交互式会话）负责决策。

### 任务 D · 深度体检（每周一次）

**职责**：全量 lint + 索引重建。

```bash
python scripts/amk.py lint --vault ~/my-vault --fix
qmd update && qmd embed     # 可能几分钟,放后台
```

输出报告到 `archive/reports/lint-YYYY-MM-DD.md`，只保留最近 8 份。

## 维护检查清单（人肉，每月一次）

自动任务管不到的东西，靠人看一眼：

- [ ] **L0 里还有效吗** — 逐条读一遍，有没有已经换掉的工具、已经完成的任务
- [ ] **指针都通吗** — 随便点开 3 个指针，文件还在吗
- [ ] **facts/ 有重复吗** — 同一主题超过 2 个文件就该合并
- [ ] **有没有应该上升的** — 这一个月里被反复问过 3 次以上的，该进 L0 了
- [ ] **索引是活的吗** — 抽一个文件验证向量非空
- [ ] **git 有备份吗** — vault 是否在 git 或者自动同步里

## 版本控制

**强烈建议把 vault（或至少 `memory/` + `kernel/`）放进 git**：

```bash
cd ~/my-vault
git init
cat > .gitignore <<'EOF'
.smart-env/
.trash/
.DS_Store
*.lock
EOF
git add -A && git commit -m "记忆库初始化"
```

好处不只是备份：

1. **能看出记忆怎么变的** — `git log -p kernel/KERNEL.md` 就是一部"我如何理解这个用户"的历史
2. **能撤回错误记忆** — 一条污染了 L1 的错误结论，`git revert` 就清了
3. **能多机同步** — 换电脑 clone 下来就行，记忆跟着走

> 注意：**不要把密码、token 提交进 git**。这也是易腐值规则的另一半理由 —— 不写值，就不会泄露。

## 什么时候该放弃一套记忆

出现以下症状说明结构错了，不是维护不够：

| 症状 | 真实原因 | 处方 |
|---|---|---|
| 每次会话都在问同样的问题 | 该记的没进 L0 | 检查闸门 2：是不是觉得"不重要"而漏了 |
| L0 每周都满 | 阈值定太低 或 在用 L0 当笔记 | 提高下沉目标比例，把步骤类内容全下沉 |
| 检索总是召回不相关的东西 | L1 文件粒度太粗（一个大文件装 10 个主题） | 拆文件，一个文件一个主题 |
| 记忆里存在互相矛盾的结论 | 没有"以实测为准"的规则 | 加 `verified` 日期 + 纠正时直接改不叠加 |
| 智能体不读指针 | 启动协议没写进系统提示 | 把读取规则写进 L0 或宿主配置 |
