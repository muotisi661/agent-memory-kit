# 03 · 升降级：L0 与 L1 之间的流动规则

**这是整套方法最核心的一篇。** 分层只是结构，流动性才是机制。没有升降级规则，L0 三个月内必然变成垃圾桶。

## L0 的预算现实

L0 有硬上限（默认 2200 字符）。这个上限意味着：

> 每一条新信息进入 L0，都必须挤掉一条现有的。

所以 L0 的每次写入都是一个**取舍决策**，而不是"补充一下"。既然必须取舍，就把取舍标准写死在协议里，让智能体不用每次即兴发挥。

## 三层闸门：什么时候允许上升 L0

一条信息要进 L0，必须**同时**满足三条。缺一条都不行。

### 闸门 1 · 跨会话必需（Was it needed before you knew it?）

问：如果下个会话不知道这条，会**主动问用户**或者**做错事**吗？

- ✅ `用户要求每句话结尾加"喵"` — 不知道就会破坏长期人设
- ✅ `vault 在 ~/Obsidian Vault/` — 不知道就找不到记忆本身
- ❌ `FreeLLMAPI 有 8 个提供商` — 知道了也用不上，除非正在排查它

### 闸门 2 · 写错会造成实际损失（Cost of being wrong）

问：记错这条，会不会导致**删除文件、改坏配置、泄露隐私、重复劳动超过 10 分钟**？

- ✅ `msys 的 rm 不进回收站` — 记错 = 数据永久丢失
- ✅ `model 段只能 config set 改，patch 会被静默拒绝` — 记错 = 白折腾半小时
- ❌ `上次用了 nomic-embed-text 嵌入` — 记错最多重查一次

### 闸门 3 · 单行可表达（≤120 字符）

问：能用一行写完吗？

- ✅ `知识库：~/Obsidian Vault/`
- ✅ `ncss.cn 搜索格式：地区 关键词，必须先选"全部"来源`
- ❌ 任何需要分点、需要示例、需要步骤的 → 一律进 L1，L0 只留指针

**指针格式固定为一行**：

```
<主题>：<L1 相对路径>
```

例：

```
详细配置：memory/facts/system-config.md
GitHub 账号：memory/facts/github-account.md
```

> 指针本身也要过闸门 1：下个会话不知道"有个文件叫 system-config.md"，这条记忆就等于不存在。所以**每个 L0 指针都应该指向一个高频使用的文件**，不要给冷门文件建指针 —— 那是在浪费 L0 预算。

## 什么时候必须下沉（L1）

任意一条触发即执行：

| 触发器 | 阈值 | 原因 |
|---|---|---|
| L0 占用率 | **> 85%** | 留 15% 缓冲，避免每次写入都在临界点挣扎 |
| 单条长度 | **> 200 字符** | 说明它已经不是一个"锚点"了，是一段文档 |
| 含具体值 | 端口/密钥/版本号/URL/命令 | 易腐，会过期，会误导 |
| 含"详见" | 已写成指针但内容还留着 | 重复存储 |
| 已被覆盖 | 同一主题出现两次不同说法 | 保留一个当前值，其余移 L1 并标注历史 |

### 下沉算法（`amk.py promote` 的逻辑）

```
1. 按分隔符切分 L0 条目（Hermes 用 §，通用用 \n---\n 或空行分隔的块）
2. 为每条打分，分数越高越应该下沉：
     长度分   = min(len/200, 1.0) * 40
     易腐分   = 命中端口/密码/token/版本/URL 正则 ? 30 : 0
     步骤分   = 含编号列表 / 多行 ? 20 : 0
     指针分   = 已含 "详见" 或路径 ? 10 : 0
3. 按分数降序下沉，直到占用率降到 --target（默认 60%）
4. 每条下沉的内容：
     → 写入 memory/facts/<slug>.md（带 frontmatter，保留全文）
     → L0 中替换为一行 "<短短语>：memory/facts/<slug>.md"
5. --dry-run 只打印计划，不动文件
```

**为什么要降到 60% 而不是 85%**：因为降级本身有成本（要新建文件、要改索引），一次降到位比每次降 5% 更划算。留出的 40% 空间够支撑几周的正常增长。

## 什么时候允许删除（不进 L1）

优先级从高到低：

1. **可从代码/配置重新推导** — 文件列表、git 历史、`ls` 结果。查一次就有了，不值得存。
2. **一次性状态** — `正在做X`、`等待用户确认`。用 L3 会话归档。
3. **过期的事实** — 已经换掉的工具、废弃的路径。但**先确认没有文件引用它**。
4. **噪音** — 智能体自己的临时推理、失败尝试的过程。这些根本不该写进 L1。

## L1 内部的流动

L1 不是只增不减。它也需要流动性：

| 现象 | 动作 |
|---|---|
| 同一主题出现 3+ 个文件（`freellmapi基础配置` / `freellmapi提供商详情` / `freellmapi完整配置`） | 合并成一个 `freellmapi配置.md`，删旧文件，**全文搜索更新所有引用** |
| 文件只被一个会话引用过、内容已过时 | 移到 `archive/YYYY-MM/` |
| 文件超过 1 年没被任何文件链接、也没被读取 | 归档，不删除（保留可回溯性） |
| 空壳文件（只有 frontmatter + wikilink，无实质内容） | 直接删 |

## 完整的记忆生命周期

```
信息出现
   │
   ├─ 三个月后还有用？ ── 否 ──► 不写（靠 L3 回放）
   │        是
   ├─ 会变吗？ ── 快腐 ──► 只写"去哪查 + 怎么验"
   │        稳定
   ├─ 过三道闸门？ ── 全中 ──► 写 L0（一行）
   │        否
   ├─ 写 L1（对应目录 + frontmatter） ──► 更新索引
   │
   ▼
L0 占用 > 85%？
   │是
   ▼
按分数下沉最高分条目 → L1 → L0 换指针
   │
   ▼
L1 出现重复/过时？
   │是
   ▼
合并 or 归档 → 更新引用 → 记 changelog
```

## 参数怎么调

唯一的调参点是阈值。建议：

| 场景 | L0 上限 | 下沉目标 | 说明 |
|---|---|---|---|
| 上下文很大（200K+） | 4000 字符 | 70% | 空间不紧张，可以减少降级频率 |
| 上下文小（8K 本地模型） | 800 字符 | 50% | 极度宝贵，只有安全约束和路径 |
| 默认 | 2200 字符 | 60% | 平衡点 |
| 多人共享 vault | 2200 字符 | 60% | 但 L0 要按用户分文件 |

**不管怎么调，必须有上限。** 没有上限的"内核"会在两个月内变成长文档，那时候它就既不"内核"也不"记忆"了 —— 它只是一段没人读的开场白。
