# 06 · 反模式：真实踩过的坑

每一条都是实际发生过的，不是理论推演。按"看起来像什么 → 实际是什么 → 怎么防"写。

---

## 1. 文档写了架构 ≠ 系统在跑

**看起来像**：技能文档/SKILL.md/README 把架构、目录、流程描述得非常完整。智能体读到后自信地说"你的记忆系统已配置完成"。

**实际是**：目录根本不存在，或者存在但是空的。文档是**意图**，不是**状态**。

**为什么危险**：智能体会基于文档编造后续回答（"你的用户画像在 user-profiles/wang-kai.md 里" —— 而那个文件不存在）。

**防法**：

```bash
# 任何"已配置"的断言,都必须有实际输出支撑
ls -la "$VAULT/memory/" && ls "$VAULT/memory/facts/" | wc -l
```

```python
# 更严格:文件存在 + 非空 + 能解析
files = list(Path(vault, "memory/facts").glob("*.md"))
assert files and all(f.stat().st_size > 200 for f in files)
```

**规则**：涉及记忆的断言，先读文件再说话。绝对不要凭文档描述回答"你有什么记忆"。

## 2. 自动整理任务会吃掉记忆目录

**看起来像**：每天晚上有个"知识库自动整理"任务，帮你去重、分类、打标签。很贴心。

**实际是**：它会把 `memory/`、`kernel/` 下的文件当成"待分类的普通笔记"，移动到 `wiki/entities/` 或者合并进别的文件。第二天记忆系统在，但内容是空的。

**为什么会发生**：从模型视角看，`memory/facts/某配置.md` 和 `notes/某配置.md` 没有任何区别 —— 都是"一个可以归类的 markdown"。它不知道前者是系统的一部分。

**防法**（按可靠性排序）：

1. **白名单写进提示词**（必要，不充分）
   ```markdown
   ## 🚫 保护白名单
   以下目录禁止移动/删除/重命名：memory/ kernel/ archive/ scripts/
   ```
2. **文件级锁标记**：记忆文件 frontmatter 加 `protected: true`，整理任务跳过
3. **权限隔离**（最可靠）：整理任务运行在不同的 vault 副本上，或者干脆用只读挂载
4. **事后再检查**：整理报告里必须包含"移动了哪些文件"的清单，人工过一遍

**恢复方法**：

```bash
# 从 wiki/entities 搬回来
mv "$VAULT/wiki/entities/某配置.md" "$VAULT/memory/facts/"
```

或者直接 `git checkout` —— 这是把 vault 放进 git 的又一个理由。

## 3. 索引"成功"但向量是空的

**看起来像**：嵌入配置改好了，插件显示"索引完成"。

**实际是**：嵌入模型根本没加载，`vec: []`，所有向量都是空数组。语义搜索返回随机结果或者什么都返回不了。整个过程**没有任何报错**。

**为什么危险**：静默失败最有欺骗性。你会以为记忆系统工作正常，直到某天需要它的时候发现搜不到任何东西。

**防法**：

```bash
# 抽查真实文件的向量维度和前几个值
grep -o '"vec":\[[^]]*\]' .smart-env/multi/<file>.ajson | tail -1 | head -c 120
# 正常： "vec":[-0.037,0.016,0.026,...]
# 异常： "vec":[]

# 维度必须匹配模型
grep -o '"vec":\[[^]]*\]' .smart-env/multi/<file>.ajson | tail -1 | tr ',' '\n' | wc -l
# nomic-embed-text = 768
```

**检查日志里有没有加载失败**：

```bash
grep '"error"' .smart-env/multi/*.ajson | head
grep 'load_failed' .smart-env/event_logs/* 2>/dev/null | head
```

**规则**：任何"索引已建"的断言，必须拿一个**真实文件**抽查非空向量。文件数多不能证明向量有内容。

## 4. 易腐值写死 → 三个月后全是错的

**看起来像**：把端口、密码、版本号、路径完整写进记忆，下次直接用，很省事。

**实际是**：这些值会变。变了之后记忆里的旧值**看起来仍然权威**（它就在 L0 里），智能体会拿它当真，然后在错误的端口上排查一小时。

**更糟的情况**：同一个值散落在 4 个文件里，其中 2 个是错的。你甚至不知道该信哪个。

**防法**：

| 不要写 | 改成写 |
|---|---|
| `端口: 3001` | `端口见 server/.env，实测 curl -s localhost:$PORT/v1/models` |
| `密码: xxx` | `凭据在系统钥匙串/银行级加密库，通过工具调用获取` |
| `版本: v4.1.3` | `版本查 `npm ls obsidian-local-rest-api`` |
| `路径: ~/Obsidian Vault` | 路径可以写 —— 但加 `verified: 2026-10-16` |

**纠正时的规则**：以实测为准。实测和文档冲突 → **直接改文件**，更新 `verified` 日期。
**不要**写成：

```markdown
端口：3001
UPDATE: 其实是 3000
UPDATE2: 2026-07 又改回 3001 了
```

下一个会话会在这里迷失。正确做法是只保留当前真实值 + 验证日期。

## 5. L0 当垃圾桶 → 满了 → 什么都记不住

**看起来像**：每条信息都挺有用，都放进内核，反正才几十字。

**实际是**：几十条几十字之后，L0 到了上限。此时新信息进不来，只能删旧的。而在"满了"的压力下，删除决策是**即兴的、没有标准的**，很容易删掉安全约束留下一条无关紧要的路径。

**根因**：没有预先定好取舍标准。

**防法**：本 kit 的 [03-promotion-demotion.md](03-promotion-demotion.md) 就是为此而写。核心是三闸门：

> 跨会话必需 **且** 写错有实际损失 **且** 单行可表达（≤120 字符）

过不了第三闸门的（步骤、配置、示例）**一开始就不该进 L0**。在入口处拦住，比在满了之后清理便宜十倍。

## 6. 用覆盖代替追加 → 历史没了

**看起来像**：更新一个配置文件，直接 `write_file` 整个覆盖成新版本。

**实际是**：丢掉了"为什么改成这样"。三个月后看到当前配置，不知道它是怎么演化的，也不知道之前踩过什么坑。

**防法**：

| 内容 | 操作 |
|---|---|
| 一篇文章的当前状态 | 覆盖（正文只留当前真值） |
| 变更历史 | 追加到 `changelog.md`（一行一条：日期 + 改了什么 + 为什么） |
| 踩坑记录 | 追加（旧坑不会因为修好了就不存在） |
| 被取代的方案 | 归档到 `archive/`，原文件留一行"已被 X 取代" |

`changelog.md` 的格式：

```markdown
## 2026-10-16
- L0 下沉 3 条到 facts/（占用 92% → 61%）
- 合并 freellmapi 三份重复配置为一份
- 修正端口记录：3000 → 3001（实测确认）
```

## 7. 绑定云端记忆服务

**看起来像**：接一个记忆 API，省事，还能跨设备。

**实际是**：额度耗尽的那天返回 `402 Payment Required`，记忆不可读。想迁移？先把数据导出来 —— 而很多服务不给你导出。

**这不是说不该用云端**，而是说：**必须有一条纯本地的可用路径**。

**防法**：

1. 本地 Markdown 是**主存**，云端只能是索引/加速层
2. 定期导出（`amk.py lint` 顺便检查"最近一次导出时间"）
3. 迁移触发器写进监控：余额 < 20%、API 错误率上升、服务商公告

**真实信号**：`402 Payment Required` 是明确的迁移发令枪，出现当天就该切换。别等到"下个月再说"。

## 8. 只用语义检索，不用精确路径

**看起来像**：所有记忆访问都走 `search("关键词")`，很智能。

**实际是**：
- 检索有噪声（相似度高的不一定是需要的）
- 检索有成本（每次一次模型调用或一次 IO）
- 检索会漏（关键词选错了就召不回来）
- 关键信息不能被"漏"（安全约束漏一次就出事）

**防法**：

```
已知路径 → 直接读文件（90% 的情况）
记不清文件名 → L2 召回（10% 的情况）
安全/硬性约束 → 不进检索，永远在 L0 里
```

**L1 的目录设计要为此服务**：路径本身就是最强索引。`memory/procedures/部署静态站.md` 让智能体不用搜索就知道该读哪个文件。

## 9. 记忆之间自相矛盾，且没有裁决规则

**看起来像**：两个文件对同一个事实有不同记载。都"有出处"。

**实际是**：智能体会随机会挑一个执行，或者把两个都告诉用户，让用户困惑。

**防法**：

1. 每个事实类文件带 `verified: YYYY-MM-DD`
2. L0/L1 里写死一条规则：**实测 > 新日期 > 旧日期**
3. `amk.py lint` 检查同一主题的多个文件（同名 slug 变体）并警告

---

## 10. 过度确认：每次都播报"我已读取你的记忆"

**看起来像**：礼貌、透明、让用户知道记忆生效了。

**实际是**：每次会话开头 200-300 字的废话。用户第三次看到就想关掉这个功能。

**规则**：

- 读取记忆是**背景动作**，不是**汇报内容**
- 只在记忆矛盾或明显过时的时候说一句
- 用户问"你记得我吗"的时候才展示记忆内容

---

## 一句话总结

> 记忆系统的绝大部分故障不是"记不住"，而是**记错了还当真**。
> 所以规则的重心应当放在：**入口卡严（写什么）、过期即改（怎么维护）、实测优先（信谁）**。
