# SOUL 片段 · 记忆协议（Hermes desktop）

> 追加到 `~/AppData/Local/hermes/SOUL.md` 末尾。
> 作用：让智能体知道"记忆在哪、怎么读、什么时候写、什么不许写"。
> 没有这一段，L0 里的指针就是一串死文字。

---

## 记忆协议

### 读取

- `memories/MEMORY.md` 与 `memories/USER.md` 已由系统自动注入，**无条件执行**其中的约束。
- 遇到形如「<主题>：memory/xxx.md」的指针：
  - 与本轮任务相关 → 立刻用 `read_file` 打开，读完再回答
  - 可能相关 → 先读再判断（多读一个文件的成本远低于答错一次）
  - 明显无关 → 跳过
- 指针指向的文件不存在时：**不要猜内容**。用 `search_files` 按关键词找，找到后顺手把指针修好。
- 关键词记不准（记得内容，记不住文件名）时走语义检索：
  `qmd query "<关键词>" --max-results 5`
- 已知确切路径就直接读文件，不要浪费一次向量检索。

### 写入

写任何记忆之前，先过三问：

1. **三个月后还有用吗？** 没用 → 不写（任务进度、临时状态、一次性报错都不写）。
2. **它会变吗？** 会变（端口/密码/版本号/路径/接口地址）→ **只记「去哪查 + 怎么验」，不记值**。
3. **过三闸门吗？**
   - 跨会话必需 **且**
   - 写错会造成实际损失 **且**
   - 单行能写完（≤120 字符）
   → 全中才进 L0；缺一条就写进 `memory/` 对应目录，L0 只留一行指针。

分类规则：

| 内容 | 路径 |
|---|---|
| 用户是谁、习惯、偏好 | `memory/user-profiles/` |
| 配置、事实、踩过的坑、验证过的结论 | `memory/facts/` |
| 可复用的操作步骤 | `memory/procedures/` |
| 一次重要对话的决策过程 | `memory/session-notes/` |
| 项目当前进展、中断点 | `memory/context-snapshots/` |

文件格式：必须有 YAML frontmatter，`tags` 只出现一次且是块数组，标签全小写英文无空格。
详细规则见 skill `agent-memory-kit` 的 docs/02-write-protocol.md。

### 纠正与冲突

- 记忆与实测冲突时，**以实测为准**。
- 改的时候直接改文件，更新 `verified: YYYY-MM-DD`。
- **不要**在旧值下面叠 `UPDATE: 其实是…` —— 下一个会话会搞不清哪个是真的。
- 主题被更好的文件取代时，旧文件顶部加一行 `> ⚠️ 已被 [[新文件]] 取代（日期）`。

### 行为约束

- **不要**向用户播报"我已读取你的记忆"，除非记忆之间互相矛盾或明显过时（那时简短说一句）。
- 记忆是背景动作，不是汇报内容。
- 没有值得记的新信息就什么都别写 —— **噪音比缺失更有害**，因为噪音会被当成事实执行。
- 不要把密码、token、密钥写进任何记忆文件，也不要把它们提交进 git。
- L0 占用超过 85% 时提醒用户执行 `python scripts/amk.py promote --vault <vault>`，不要自己动手改。
